# Design: 조문 조회 및 변경 감지 기능

**Feature ID**: article-tracking
**Design Version**: 2.0 (Revised)
**Created**: 2026-02-14
**Revised**: 2026-02-14
**Plan Document**: [조문-조회-및-변경-감지-기능.plan.md](../../01-plan/features/조문-조회-및-변경-감지-기능.plan.md)

## ⚠️ 핵심 설계 방향

**현재 시스템 구조**:
```
조례(Ordinance) → 관련 법령(Law) → 관련 조문(Article)
```

**목표**:
1. 조문 변경 감지 → 해당 조문 → 연계된 법령 → 연계된 조례 개정 필요 판단
2. 자치법규 상세 페이지에 "관련 조문" 탭 추가하여 연계 법령의 조문 표시
3. 조문 변경 시 자동으로 관련 조례의 `needs_revision` 플래그 업데이트

## 1. Architecture Overview

### 1.1 System Architecture

```
┌─────────────────────────────────────────────────────────┐
│                    Frontend (React)                     │
├─────────────────────────────────────────────────────────┤
│  OrdinanceDetail (자치법규 상세)                         │
│    ├── [기존 탭들]                                       │
│    └── [관련 조문] 탭 ← NEW                              │
│         ├── 연계 법령 목록                               │
│         └── 각 법령의 조문 목록 + 변경 이력              │
└─────────────────────────────────────────────────────────┘
                         │ REST API (JSON)
                         ▼
┌─────────────────────────────────────────────────────────┐
│              Backend API (FastAPI)                      │
├─────────────────────────────────────────────────────────┤
│  /api/v1/ordinances/{id}/articles  ← NEW               │
│    → 조례와 연계된 법령들의 조문 목록 조회               │
│                                                         │
│  /api/v1/laws/{id}/articles  ← NEW                     │
│    → 특정 법령의 조문 목록 조회                         │
│                                                         │
│  /api/v1/articles/sync  ← 백그라운드 동기화             │
│    → 법제처 API에서 조문 조회 및 변경 감지              │
└─────────────────────────────────────────────────────────┘
         │                              │
         ▼                              ▼
┌──────────────────────┐    ┌───────────────────────────┐
│    PostgreSQL        │    │  MolegClient (법제처 API)  │
├──────────────────────┤    ├───────────────────────────┤
│  - ordinances        │    │  - get_law_detail()       │
│  - laws              │    │    → 법령의 조문 조회      │
│  - ordinance_law_    │    │  - get_law_history()      │
│    mappings (기존)   │    │    → 변경 이력 조회        │
│  - articles (NEW)    │    └───────────────────────────┘
│  - article_changes   │
│    (NEW)             │
└──────────────────────┘
         ▲
         │ (일 1회 오전 9시)
┌──────────────────────┐
│    Celery Worker     │
├──────────────────────┤
│  Task: sync_articles │
│    1. 모든 법령의 조문 조회 (법제처 API)                 │
│    2. 조문 내용 해시 비교 → 변경 감지                    │
│    3. 변경 시:                                          │
│       - article_changes 레코드 생성                     │
│       - 해당 조문 → 법령 → 조례 역추적                  │
│       - 조례.needs_revision = 1 업데이트                │
└──────────────────────┘
```

**데이터 흐름 (3단계 연계)**:

```
┌─────────────┐     ordinance_law_mappings     ┌──────────┐
│  Ordinance  │ ──────────────────────────────► │   Law    │
│  (조례)     │                                 │  (법령)  │
└─────────────┘                                 └──────────┘
                                                      │
                                                      │ law_id (FK)
                                                      ▼
                                                ┌──────────┐
                                                │ Article  │
                                                │ (조문)   │
                                                └──────────┘
                                                      │
                                                      │ 변경 감지 시
                                                      ▼
                                                ┌──────────────┐
                                                │ ArticleChange│
                                                │ (변경 이력)  │
                                                └──────────────┘

역추적 (조문 변경 → 조례 개정 필요):
ArticleChange → Article → Law → OrdinanceLawMapping → Ordinance
                                                          ↓
                                                   needs_revision = 1
```

### 1.2 Component Responsibilities

| Component | Responsibility |
|-----------|----------------|
| **OrdinanceDetail** (수정) | 자치법규 상세 + "관련 조문" 탭 추가 |
| **RelatedArticlesTab** (신규) | 연계 법령별 조문 목록 표시 |
| **ArticleChangeHistoryModal** (신규) | 조문 변경 이력 및 diff 비교 |
| **ArticleService** (Backend) | 조문 CRUD, 조례별 조문 조회 로직 |
| **ArticleSyncService** (Backend) | 법제처 API 동기화, 변경 감지, 조례 역추적 |
| **MolegClient** (확장) | 법제처 API 호출 (조문 포함) |
| **Celery Worker** | 정기 동기화 작업 실행 |

### 1.3 핵심 변경 사항

**기존 구조 유지**:
- `ordinances` 테이블
- `laws` 테이블
- `ordinance_law_mappings` 테이블 (조례-법령 N:N)

**신규 추가**:
- `articles` 테이블 (법령-조문 1:N, law_id FK)
- `article_changes` 테이블 (조문 변경 이력)
- OrdinanceDetail에 "관련 조문" 탭
- 조문 변경 → 조례 needs_revision 자동 업데이트 로직

## 2. Database Schema

### 2.1 ERD (Entity Relationship Diagram)

**핵심 구조**: 조례 → 법령 → 조문 (3단계 연계, 기존 테이블 활용)

```
┌──────────────────┐                    ┌──────────────────┐
│   ordinances     │                    │      laws        │
│   (조례)         │                    │     (법령)       │
│ - id             │                    │ - id             │
│ - name           │                    │ - law_name       │
│ - department     │                    │ - law_id         │
│ - needs_revision │← 조문 변경 시 업데이트│ - proclaimed_date│
└──────────────────┘                    └──────────────────┘
         │                                       │
         │ N                                     │ 1
         │         ┌──────────────────────┐      │
         └────────►│ ordinance_law_       │◄─────┘
                   │ mappings (기존)      │
                   │                      │
                   │ - id                 │
                   │ - ordinance_id (FK)  │
                   │ - law_id (FK)        │
                   │ - related_articles   │← 관련 조문번호 (참고용)
                   └──────────────────────┘
                                ▲
                                │ 참조 (조례 → 법령 → 조문 추적)
                                │
                   ┌────────────┴──────────┐
                   │      articles         │
                   │      (조문) NEW       │
                   │                       │
                   │ - id                  │
                   │ - law_id (FK)         │
                   │ - article_no          │
                   │ - article_title       │
                   │ - article_content     │
                   │ - paragraphs (JSONB)  │
                   │ - content_hash        │← SHA-256 (변경 감지용)
                   │ - last_synced_at      │
                   └───────────────────────┘
                            │ 1
                            │
                            │ N
                   ┌────────▼──────────────┐
                   │   article_changes     │
                   │   (조문 변경 이력) NEW│
                   │                       │
                   │ - id                  │
                   │ - article_id (FK)     │
                   │ - change_date         │
                   │ - change_type         │
                   │ - old_content         │
                   │ - new_content         │
                   │ - old_hash            │
                   │ - new_hash            │
                   │ - diff_html           │
                   │ - notified            │
                   └───────────────────────┘

조문 변경 감지 시 역추적 경로:
1. ArticleChange 생성 (변경 감지)
2. Article.law_id → Law 조회
3. Law.id → OrdinanceLawMapping 조회 (해당 법령과 연계된 조례들)
4. Ordinance.needs_revision = 1 업데이트
```

**중요**:
- `ordinance_article_mappings` 테이블은 **생성하지 않음**
- 이유: 조례 ↔ 법령 매핑은 이미 `ordinance_law_mappings`에 있음
- 조례의 관련 조문은 `ordinance_law_mappings.law_id → articles.law_id`로 조회

### 2.2 Table Definitions

#### 2.2.1 `articles` 테이블

```sql
CREATE TABLE articles (
    id SERIAL PRIMARY KEY,
    law_id INTEGER NOT NULL REFERENCES laws(id) ON DELETE CASCADE,

    -- 조문 식별
    article_no VARCHAR(50) NOT NULL,          -- 제1조, 제2조의2, 부칙 제1조 등
    article_title VARCHAR(500),                -- 조문 제목 (목적, 정의 등)

    -- 조문 내용
    article_content TEXT NOT NULL,             -- 조문 전체 내용
    paragraphs JSONB,                          -- 항, 호, 목 구조 (JSON)

    -- 변경 감지용
    content_hash VARCHAR(64) NOT NULL,         -- SHA-256 해시

    -- 법제처 API 원본 정보
    mst_seq INTEGER,                           -- 법령MST 순번
    jo_seq INTEGER,                            -- 조문 순번

    -- 메타데이터
    last_synced_at TIMESTAMP,                  -- 마지막 동기화 시점
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),

    UNIQUE(law_id, article_no)
);

-- 인덱스
CREATE INDEX idx_articles_law_id ON articles(law_id);
CREATE INDEX idx_articles_content_hash ON articles(content_hash);
CREATE INDEX idx_articles_article_no ON articles(article_no);
CREATE INDEX idx_articles_last_synced ON articles(last_synced_at);
```

**paragraphs JSONB 구조 예시:**

```json
{
  "paragraphs": [
    {
      "type": "paragraph",
      "no": "1",
      "content": "지방자치단체는 주민의 복리에 관한 사무를 처리한다.",
      "items": []
    },
    {
      "type": "paragraph",
      "no": "2",
      "content": "지방자치단체의 종류는 다음과 같다.",
      "items": [
        {
          "type": "item",
          "no": "1",
          "content": "특별시, 광역시 및 특별자치시"
        },
        {
          "type": "item",
          "no": "2",
          "content": "도 및 특별자치도"
        }
      ]
    }
  ]
}
```

#### 2.2.2 `ordinance_article_mappings` 테이블

```sql
CREATE TABLE ordinance_article_mappings (
    id SERIAL PRIMARY KEY,
    ordinance_id INTEGER NOT NULL REFERENCES ordinances(id) ON DELETE CASCADE,
    article_id INTEGER NOT NULL REFERENCES articles(id) ON DELETE CASCADE,

    -- 연계 정보
    mapping_reason TEXT,                       -- 연계 사유 또는 메모
    related_article_nos VARCHAR(200),          -- 관련 조례 조문번호 (쉼표 구분)

    -- 추적 정보
    created_by INTEGER REFERENCES users(id),   -- 연계 등록자
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),

    UNIQUE(ordinance_id, article_id)
);

-- 인덱스
CREATE INDEX idx_ordinance_article_mappings_ordinance_id
    ON ordinance_article_mappings(ordinance_id);
CREATE INDEX idx_ordinance_article_mappings_article_id
    ON ordinance_article_mappings(article_id);
```

#### 2.2.3 `article_changes` 테이블

```sql
CREATE TABLE article_changes (
    id SERIAL PRIMARY KEY,
    article_id INTEGER NOT NULL REFERENCES articles(id) ON DELETE CASCADE,

    -- 변경 정보
    change_date DATE NOT NULL,                 -- 공포일자 (법령 기준)
    change_type VARCHAR(20) NOT NULL,          -- 'created', 'updated', 'deleted'

    -- 변경 내용
    old_content TEXT,                          -- 이전 조문 내용
    new_content TEXT,                          -- 새 조문 내용
    old_hash VARCHAR(64),                      -- 이전 해시
    new_hash VARCHAR(64),                      -- 새 해시

    -- diff 정보 (optional)
    diff_html TEXT,                            -- HTML diff (ui 표시용)

    -- 감지 정보
    detected_at TIMESTAMP DEFAULT NOW(),       -- 변경 감지 시점
    notified BOOLEAN DEFAULT FALSE,            -- 알림 발송 여부

    created_at TIMESTAMP DEFAULT NOW()
);

-- 인덱스
CREATE INDEX idx_article_changes_article_id ON article_changes(article_id);
CREATE INDEX idx_article_changes_change_date ON article_changes(change_date);
CREATE INDEX idx_article_changes_detected_at ON article_changes(detected_at);
CREATE INDEX idx_article_changes_notified ON article_changes(notified);
```

```python
"""
Article (조문) model
"""
from datetime import datetime, date
from typing import List, Optional, TYPE_CHECKING
from sqlalchemy import String, Text, Date, DateTime, Integer, ForeignKey, Index
from sqlalchemy.dialects.postgresql import JSONB
from sqlalchemy.orm import Mapped, mapped_column, relationship

from backend.core.database import Base

if TYPE_CHECKING:
    from backend.models.law import Law
    from backend.models.ordinance_article_mapping import OrdinanceArticleMapping
    from backend.models.article_change import ArticleChange


class Article(Base):
    """
    법령 조문 테이블

    법제처 lawService API 응답의 조문 정보 기반
    """
    __tablename__ = "articles"

    id: Mapped[int] = mapped_column(primary_key=True)
    law_id: Mapped[int] = mapped_column(
        Integer,
        ForeignKey("laws.id", ondelete="CASCADE"),
        nullable=False
    )

    # 조문 식별
    article_no: Mapped[str] = mapped_column(String(50), nullable=False)
    article_title: Mapped[Optional[str]] = mapped_column(String(500))

    # 조문 내용
    article_content: Mapped[str] = mapped_column(Text, nullable=False)
    paragraphs: Mapped[Optional[dict]] = mapped_column(JSONB)

    # 변경 감지용
    content_hash: Mapped[str] = mapped_column(String(64), nullable=False)

    # 법제처 API 원본 정보
    mst_seq: Mapped[Optional[int]] = mapped_column(Integer)
    jo_seq: Mapped[Optional[int]] = mapped_column(Integer)

    # 메타데이터
    last_synced_at: Mapped[Optional[datetime]] = mapped_column(DateTime)
    created_at: Mapped[datetime] = mapped_column(DateTime, default=datetime.utcnow)
    updated_at: Mapped[datetime] = mapped_column(
        DateTime,
        default=datetime.utcnow,
        onupdate=datetime.utcnow
    )

    # Relationships
    law: Mapped["Law"] = relationship(back_populates="articles")
    ordinance_mappings: Mapped[List["OrdinanceArticleMapping"]] = relationship(
        back_populates="article",
        cascade="all, delete-orphan"
    )
    changes: Mapped[List["ArticleChange"]] = relationship(
        back_populates="article",
        cascade="all, delete-orphan"
    )

    __table_args__ = (
        Index('idx_articles_law_id', 'law_id'),
        Index('idx_articles_content_hash', 'content_hash'),
        Index('idx_articles_article_no', 'article_no'),
        Index('idx_articles_last_synced', 'last_synced_at'),
    )

    def __repr__(self) -> str:
        return f"<Article(id={self.id}, law_id={self.law_id}, no={self.article_no})>"
```

```python
"""
OrdinanceArticleMapping (조례-조문 연계) model
"""
from datetime import datetime
from typing import Optional, TYPE_CHECKING
from sqlalchemy import String, Text, DateTime, Integer, ForeignKey, Index
from sqlalchemy.orm import Mapped, mapped_column, relationship

from backend.core.database import Base

if TYPE_CHECKING:
    from backend.models.ordinance import Ordinance
    from backend.models.article import Article
    from backend.models.user import User


class OrdinanceArticleMapping(Base):
    """
    조례-조문 연계 테이블

    특정 조례가 어느 법령의 어느 조문과 연계되는지 관리
    """
    __tablename__ = "ordinance_article_mappings"

    id: Mapped[int] = mapped_column(primary_key=True)
    ordinance_id: Mapped[int] = mapped_column(
        Integer,
        ForeignKey("ordinances.id", ondelete="CASCADE"),
        nullable=False
    )
    article_id: Mapped[int] = mapped_column(
        Integer,
        ForeignKey("articles.id", ondelete="CASCADE"),
        nullable=False
    )

    # 연계 정보
    mapping_reason: Mapped[Optional[str]] = mapped_column(Text)
    related_article_nos: Mapped[Optional[str]] = mapped_column(String(200))

    # 추적 정보
    created_by: Mapped[Optional[int]] = mapped_column(
        Integer,
        ForeignKey("users.id")
    )
    created_at: Mapped[datetime] = mapped_column(DateTime, default=datetime.utcnow)
    updated_at: Mapped[datetime] = mapped_column(
        DateTime,
        default=datetime.utcnow,
        onupdate=datetime.utcnow
    )

    # Relationships
    ordinance: Mapped["Ordinance"] = relationship(back_populates="article_mappings")
    article: Mapped["Article"] = relationship(back_populates="ordinance_mappings")
    creator: Mapped[Optional["User"]] = relationship()

    __table_args__ = (
        Index('idx_ordinance_article_mappings_ordinance_id', 'ordinance_id'),
        Index('idx_ordinance_article_mappings_article_id', 'article_id'),
    )

    def __repr__(self) -> str:
        return f"<OrdinanceArticleMapping(ord={self.ordinance_id}, art={self.article_id})>"
```

```python
"""
ArticleChange (조문 변경 이력) model
"""
from datetime import datetime, date
from typing import Optional, TYPE_CHECKING
from sqlalchemy import String, Text, Date, DateTime, Integer, ForeignKey, Boolean, Index
from sqlalchemy.orm import Mapped, mapped_column, relationship

from backend.core.database import Base

if TYPE_CHECKING:
    from backend.models.article import Article


class ArticleChange(Base):
    """
    조문 변경 이력 테이블

    조문의 개정 이력을 추적하여 영향받는 조례를 파악
    """
    __tablename__ = "article_changes"

    id: Mapped[int] = mapped_column(primary_key=True)
    article_id: Mapped[int] = mapped_column(
        Integer,
        ForeignKey("articles.id", ondelete="CASCADE"),
        nullable=False
    )

    # 변경 정보
    change_date: Mapped[date] = mapped_column(Date, nullable=False)
    change_type: Mapped[str] = mapped_column(String(20), nullable=False)

    # 변경 내용
    old_content: Mapped[Optional[str]] = mapped_column(Text)
    new_content: Mapped[Optional[str]] = mapped_column(Text)
    old_hash: Mapped[Optional[str]] = mapped_column(String(64))
    new_hash: Mapped[Optional[str]] = mapped_column(String(64))

    # diff 정보
    diff_html: Mapped[Optional[str]] = mapped_column(Text)

    # 감지 정보
    detected_at: Mapped[datetime] = mapped_column(DateTime, default=datetime.utcnow)
    notified: Mapped[bool] = mapped_column(Boolean, default=False)

    created_at: Mapped[datetime] = mapped_column(DateTime, default=datetime.utcnow)

    # Relationships
    article: Mapped["Article"] = relationship(back_populates="changes")

    __table_args__ = (
        Index('idx_article_changes_article_id', 'article_id'),
        Index('idx_article_changes_change_date', 'change_date'),
        Index('idx_article_changes_detected_at', 'detected_at'),
        Index('idx_article_changes_notified', 'notified'),
    )

    def __repr__(self) -> str:
        return f"<ArticleChange(id={self.id}, article_id={self.article_id}, type={self.change_type})>"
```

## 5. Data Flow

### 5.1 조문 동기화 Flow

```
[Celery Worker - 일 1회 09:00]
    │
    ▼
1. LawSyncService.sync_articles()
    │
    ├─→ 2. DB에서 laws 목록 조회
    │      SELECT * FROM laws WHERE last_synced_at < NOW() - INTERVAL '1 day'
    │
    ├─→ 3. 각 법령에 대해:
    │      ├─→ 3.1 MolegClient.get_law_detail(law_mst)
    │      │      GET /DRF/lawService.do?MST={mst}&type=JSON
    │      │
    │      ├─→ 3.2 응답 파싱: 조문 목록 추출
    │      │
    │      ├─→ 3.3 각 조문에 대해:
    │      │      ├─→ 조문 내용 해시 생성 (SHA-256)
    │      │      ├─→ DB 조회: 기존 조문 존재 여부
    │      │      │      SELECT * FROM articles
    │      │      │      WHERE law_id={law_id} AND article_no={article_no}
    │      │      │
    │      │      ├─→ 비교:
    │      │      │   ├─ 신규: INSERT + article_changes (created)
    │      │      │   ├─ 변경: UPDATE + article_changes (updated)
    │      │      │   └─ 동일: SKIP
    │      │      │
    │      │      └─→ 변경 감지 시:
    │      │           ├─ article_changes 레코드 생성
    │      │           ├─ 연계 조례 조회
    │      │           │   SELECT o.* FROM ordinances o
    │      │           │   JOIN ordinance_article_mappings m
    │      │           │   ON o.id = m.ordinance_id
    │      │           │   WHERE m.article_id = {article_id}
    │      │           │
    │      │           └─ 조례 needs_revision 플래그 업데이트
    │      │               UPDATE ordinances
    │      │               SET needs_revision = 1
    │      │               WHERE id IN (...)
    │      │
    │      └─→ 3.4 law.last_synced_at 업데이트
    │
    └─→ 4. 동기화 결과 로깅 및 알림
```

### 5.2 조문 조회 Flow

```
[User: ArticleList 페이지 접속]
    │
    ▼
1. Frontend: articleApi.getList({ page, size, law_id, ... })
    │
    ▼
2. Backend: GET /api/v1/articles
    │
    ├─→ 3. Query 빌드:
    │      SELECT a.*, l.law_name, COUNT(m.id) as ordinance_count
    │      FROM articles a
    │      JOIN laws l ON a.law_id = l.id
    │      LEFT JOIN ordinance_article_mappings m ON a.id = m.article_id
    │      WHERE ...filters...
    │      GROUP BY a.id, l.law_name
    │      ORDER BY a.law_id, a.article_no
    │      LIMIT {size} OFFSET {(page-1)*size}
    │
    ├─→ 4. 최근 변경 여부 체크:
    │      SELECT DISTINCT article_id
    │      FROM article_changes
    │      WHERE detected_at > NOW() - INTERVAL '30 days'
    │
    └─→ 5. Response 조합:
           {
             "items": [...],
             "total": count,
             "page": page,
             "size": size
           }
```

```
[User: ArticleDetail → "연계 조례 추가" 버튼 클릭]

    ▼
1. Modal 표시: 조례 검색 및 선택

    {
      "ordinance_id": 10,
      "mapping_reason": "...",
      "related_article_nos": "..."
    }
    │
    ▼
4. Backend:
    ├─→ 권한 체크 (authenticated user)
    ├─→ 중복 체크:
    │      SELECT * FROM ordinance_article_mappings
    │      WHERE article_id={id} AND ordinance_id={ordinance_id}
    │
    ├─→ INSERT:
    │      INSERT INTO ordinance_article_mappings
    │      (article_id, ordinance_id, mapping_reason, created_by, ...)
```

## 6. Algorithm Design

### 6.1 조문 변경 감지 알고리즘

**목표**: 법제처 API에서 조회한 조문과 DB의 조문을 비교하여 변경 감지

**Input**:
- `law_id`: 법령 ID
- `api_articles`: 법제처 API 응답 조문 목록
- `db_articles`: DB의 기존 조문 목록

**Output**:
- `created`: 신규 조문 목록
- `updated`: 변경된 조문 목록
- `deleted`: 삭제된 조문 목록

**Algorithm**:

```python
def detect_article_changes(law_id: int, api_articles: List[dict]) -> dict:
    """
    조문 변경 감지 알고리즘

    Returns:
        {
            "created": List[Article],
            "updated": List[tuple[Article, str, str]],  # (article, old_hash, new_hash)
            "deleted": List[Article]
        }
    """
    import hashlib
    from datetime import datetime

    # 1. DB에서 기존 조문 조회
    db_articles = db.query(Article).filter(Article.law_id == law_id).all()
    db_article_map = {art.article_no: art for art in db_articles}

    # 2. API 조문 처리
    api_article_map = {}
    for api_art in api_articles:
        article_no = api_art['조문번호']
        content = api_art['조문내용']

        # 2.1 해시 생성 (SHA-256)
        content_hash = hashlib.sha256(content.encode('utf-8')).hexdigest()

        api_article_map[article_no] = {
            'no': article_no,
            'title': api_art.get('조문제목'),
            'content': content,
            'hash': content_hash,
            'paragraphs': parse_paragraphs(api_art)
        }

    # 3. 비교 결과 초기화
    result = {
        'created': [],
        'updated': [],
        'deleted': []
    }

    # 4. 신규 및 변경 조문 감지
    for article_no, api_data in api_article_map.items():
        if article_no not in db_article_map:
            # 4.1 신규 조문
            new_article = Article(
                law_id=law_id,
                article_no=article_no,
                article_title=api_data['title'],
                article_content=api_data['content'],
                paragraphs=api_data['paragraphs'],
                content_hash=api_data['hash'],
                last_synced_at=datetime.utcnow()
            )
            result['created'].append(new_article)

        else:
            # 4.2 기존 조문 - 해시 비교
            db_article = db_article_map[article_no]

            if db_article.content_hash != api_data['hash']:
                # 변경 감지!
                old_hash = db_article.content_hash
                old_content = db_article.article_content

                # 조문 업데이트
                db_article.article_content = api_data['content']
                db_article.article_title = api_data['title']
                db_article.paragraphs = api_data['paragraphs']
                db_article.content_hash = api_data['hash']
                db_article.last_synced_at = datetime.utcnow()

                result['updated'].append((db_article, old_content, old_hash))

    # 5. 삭제된 조문 감지
    for article_no, db_article in db_article_map.items():
        if article_no not in api_article_map:
            result['deleted'].append(db_article)

    return result


def parse_paragraphs(api_article: dict) -> dict:
    """
    법제처 API 응답의 항/호/목 구조 파싱

    Returns:
        {
          "paragraphs": [
            {
              "type": "paragraph",
              "no": "1",
              "content": "...",
              "items": [...]
            }
          ]
        }
    """
    paragraphs = []

    # 항 파싱
    for para in api_article.get('항', []):
        para_obj = {
            'type': 'paragraph',
            'no': para['항번호'],
            'content': para['항내용'],
            'items': []
        }

        # 호 파싱
        for item in para.get('호', []):
            item_obj = {
                'type': 'item',
                'no': item['호번호'],
                'content': item['호내용'],
                'subitems': []
            }

            # 목 파싱
            for subitem in item.get('목', []):
                subitem_obj = {
                    'type': 'subitem',
                    'no': subitem['목번호'],
                    'content': subitem['목내용']
                }
                item_obj['subitems'].append(subitem_obj)

            para_obj['items'].append(item_obj)

        paragraphs.append(para_obj)

    return {'paragraphs': paragraphs}


def create_article_change_record(
    article: Article,
    old_content: str,
    old_hash: str,
    law_proclaimed_date: date
):
    """
    조문 변경 이력 레코드 생성
    """
    import difflib

    # Diff HTML 생성
    diff = difflib.HtmlDiff()
    diff_html = diff.make_table(
```

### 6.2 SHA-256 해시 생성

**Why SHA-256?**
- 충돌 확률 극히 낮음 (2^256)
- 빠른 계산 속도
- 표준 라이브러리 지원

**Implementation**:

```python
import hashlib

def generate_content_hash(content: str) -> str:
    """
    조문 내용의 SHA-256 해시 생성

    Args:
        content: 조문 내용 텍스트

    Returns:
        64자 hex 문자열
    """
    # UTF-8 인코딩 후 해시
    return hashlib.sha256(content.encode('utf-8')).hexdigest()
```

### 6.3 Diff 생성 알고리즘

**Library**: Python `difflib` 모듈

**Implementation**:

```python
import difflib

def generate_diff_html(old_content: str, new_content: str) -> str:
    """
    두 조문 내용의 차이를 HTML로 생성

    Args:
        old_content: 이전 내용
        new_content: 새 내용

    Returns:
        HTML diff 테이블
    """
    diff = difflib.HtmlDiff(wrapcolumn=80)

    html = diff.make_table(
        old_content.splitlines(),
        new_content.splitlines(),
        fromdesc='이전 내용',
        todesc='새 내용',
        context=True,  # 변경된 부분 주변만 표시
        numlines=3     # 컨텍스트 라인 수
    )

    return html
```

### 9.3 Caching Strategy

**Redis 캐싱:**

```python
from redis import asyncio as aioredis
import json

class ArticleCache:
    def __init__(self, redis: aioredis.Redis):
        self.redis = redis
        self.ttl = 3600  # 1시간

    async def get_article(self, article_id: int) -> Optional[dict]:
        key = f"article:{article_id}"
        cached = await self.redis.get(key)
        if cached:
            return json.loads(cached)
        return None

    async def set_article(self, article_id: int, data: dict):
        key = f"article:{article_id}"
        await self.redis.setex(key, self.ttl, json.dumps(data))

    async def invalidate_article(self, article_id: int):
        key = f"article:{article_id}"
        await self.redis.delete(key)
```
