# Feature Specification: LLM 기반 검토의견 자동 생성

**Feature Branch**: `006-llm-review-assistant`
**Created**: 2026-02-28
**Status**: Draft
**Input**: User description: "법령 제개정이유와 조례를 LLM API에 전송하여 개정내용 요약 및 검토의견 초안을 자동 생성하는 기능"
**Constitution Ref**: I. 데이터 무결성, III. 외부 의존 격리, VI. 보안 기본 적용, VII. 사용자 중심 설계, VIII. AI 보조 활용

## 개요

법령 동기화 후 감지된 개정 법령의 **제개정이유내용**과 **개정문내용**을 해당 조례와 함께
LLM API에 전송하여:
1. **개정내용 요약**: 법령 개정의 핵심 변경사항을 한국어로 요약
2. **검토의견 초안**: 해당 조례의 개정 필요 여부에 대한 의견 초안을 자동 생성

담당자는 LLM이 생성한 초안을 참고하여 최종 검토의견을 작성한다.
LLM 결과는 **참고용(보조)**이며, 최종 판단은 반드시 담당자가 수행한다.

## Constitution 주의사항

| 원칙 | 수준 | 설명 |
|------|------|------|
| I. 데이터 무결성 | WARN | LLM 응답은 비결정론적. 원본 입력과 LLM 출력을 모두 보존해야 함 |
| III. 외부 의존 격리 | WARN | LLM API는 외부 시스템. 격리된 클라이언트 모듈로 관리. 장애 시 기존 기능 영향 없어야 함 |
| VI. 보안 기본 적용 | WARN | 법령/조례 텍스트를 외부 API로 전송. 법령 정보는 공개 데이터이므로 민감도 낮음. API 키 보안 관리 필요 |
| VIII. AI 보조 활용 | WARN | LLM 출력은 보조 도구. AI 생성 라벨 필수, 최종 판단은 담당자 수행 |

## User Scenarios & Testing

### User Story 1 - 개정내용 AI 요약 조회 (Priority: P1)

부서 담당자가 개정 검토 대상 조례의 상세 페이지에서 "AI 요약" 버튼을 클릭하면,
연결된 상위법령의 제개정이유와 개정문내용을 LLM이 분석하여 요약을 표시한다.

**Why this priority**: 법령 제개정이유 원문은 길고 복잡하여 핵심 파악이 어려움. 요약으로 검토 효율 향상.

**Independent Test**: 조례 상세 → AI 요약 버튼 → 개정내용 요약 표시

**Acceptance Scenarios**:

1. **Given** 개정 검토 대상 조례의 상세 페이지에서,
   **When** "AI 요약" 버튼을 클릭하면,
   **Then** 연결된 상위법령의 제개정이유를 LLM이 분석하여 한국어 요약을 표시한다
2. **Given** 요약이 생성된 상태에서,
   **When** 요약 내용을 확인하면,
   **Then** 주요 변경사항, 변경된 조문 목록, 조례에 미치는 영향이 구조화되어 표시된다
3. **Given** LLM API 호출이 실패하면,
   **When** 에러 발생 시,
   **Then** "AI 요약을 생성할 수 없습니다. 직접 검토해 주세요" 안내 메시지 표시, 기존 기능은 정상 동작

---

### User Story 2 - 검토의견 초안 자동 생성 (Priority: P1)

부서 담당자가 검토의견 작성 화면에서 "AI 초안 생성" 버튼을 클릭하면,
LLM이 법령 개정내용과 조례 정보를 분석하여 검토의견 초안(개정필요/개정불필요 + 사유)을 생성한다.

**Why this priority**: 검토의견 작성의 진입장벽을 낮추어 업무 효율 극대화. 핵심 가치.

**Independent Test**: 검토의견 작성 → AI 초안 생성 → 초안 내용이 입력 필드에 채워짐 → 담당자 수정 후 제출

**Acceptance Scenarios**:

1. **Given** 검토의견 작성 화면에서,
   **When** "AI 초안 생성" 버튼을 클릭하면,
   **Then** LLM이 분석한 검토의견 초안(결과: 개정필요/개정불필요, 의견 내용)이 입력 필드에 자동 채워진다
2. **Given** AI 초안이 생성된 후,
   **When** 담당자가 내용을 수정하면,
   **Then** 수정된 내용으로 검토의견이 제출된다 (AI 초안은 참고용)
3. **Given** AI 초안이 생성된 후,
   **When** 담당자가 수정 없이 그대로 제출하면,
   **Then** AI 생성 여부가 메타데이터에 기록된다 (`is_ai_generated=true`, `ai_modified=false`)

---

### User Story 3 - AI 결과 보존 및 재조회 (Priority: P2)

동일 법령-조례 조합에 대한 AI 분석 결과를 DB에 보존하고, 재조회 시 저장된 결과를 반환한다.
AI 분석은 1회만 수행되며, 결과 확정 후 재실행할 수 없다 (Constitution VIII 준수).

**Why this priority**: 1회 실행 원칙 보장 + LLM API 비용 절감 + 감사 추적성 확보.

**Independent Test**: 최초 요청 → LLM 호출 → 결과 저장 → 재조회 시 저장된 결과 반환 → AI 요약 버튼 비활성화

**Acceptance Scenarios**:

1. **Given** 동일 법령-조례 조합에 대해 AI 요약이 이미 생성된 경우,
   **When** 해당 조례 상세 페이지에 접근하면,
   **Then** 저장된 AI 요약 결과를 즉시 표시하고, "AI 요약" 버튼은 비활성화된다
2. **Given** 법령이 새로 동기화되어 제개정이유가 변경된 경우,
   **When** 해당 조례 상세 페이지에 접근하면,
   **Then** 기존 결과는 이력으로 보존하고, 새 법령 버전에 대해 AI 분석을 1회 수행할 수 있다

---

### User Story 4 - AI 분석 이력 조회 (Priority: P3)

관리자가 AI가 생성한 요약 및 검토의견 초안의 이력을 조회하여 활용도를 파악한다.

**Why this priority**: AI 활용 현황 모니터링 및 품질 평가에 필요.

**Independent Test**: 관리자 → AI 분석 이력 → 생성 건수, 채택률 확인

**Acceptance Scenarios**:

1. **Given** 관리자가 AI 분석 이력 페이지에 접근하면,
   **When** 기간별 필터를 적용하면,
   **Then** AI 요약 생성 건수, 검토의견 초안 생성 건수, 초안 채택률(수정 없이 제출 비율) 표시

---

### Edge Cases

- LLM API 응답 지연(10초 이상) 시 타임아웃 처리 및 사용자 안내
- 제개정이유내용이 없는 법령(오래된 법령, 제정 법령) → "제개정이유 데이터가 없어 AI 분석을 수행할 수 없습니다"
- 매우 긴 제개정이유(토큰 제한 초과) → 텍스트 분할 또는 요약 후 전송
- LLM이 한국어가 아닌 응답을 반환한 경우 → 재시도 또는 경고
- 동시에 여러 건의 AI 분석 요청 → Rate limiting 적용
- LLM API 키 만료/잔액 부족 → 관리자에게 알림
- AI 분석 중 네트워크 오류로 실패 → 실패 상태 기록, 해당 건에 한해 재시도 1회 허용 (성공 후 재실행 불가 원칙 적용)
- 이미 AI 분석 완료된 건에서 "AI 요약" 버튼 클릭 시도 → 버튼 비활성화로 원천 차단

## Requirements

### Functional Requirements

- **FR-001**: 조례 상세 페이지에서 연결된 상위법령의 제개정이유를 LLM에 전송하여 개정내용 요약을 생성할 수 있어야 한다
- **FR-002**: 검토의견 작성 시 LLM이 생성한 초안(결과+의견)을 입력 필드에 자동 채울 수 있어야 한다
- **FR-003**: LLM 결과는 "AI 생성" 라벨로 명확히 구분하고, 담당자의 최종 판단을 대체하지 않음을 안내해야 한다
- **FR-004**: AI 생성 검토의견에는 메타데이터(`is_ai_generated`, `ai_modified`, `ai_model`, `ai_generated_at`)를 기록해야 한다
- **FR-005**: 동일 법령-조례 조합에 대한 AI 분석은 1회만 수행하며, 결과를 DB에 보존한다. 결과 확정 후 동일 대상에 대해 재실행할 수 없다 (Constitution VIII 준수)
- **FR-005a**: 법령이 새로 동기화되어 제개정이유가 변경된 경우, 기존 결과는 이력으로 보존하고 새 법령 버전에 대해 1회 분석을 허용한다
- **FR-006**: LLM API 장애 시 기존 기능(수동 검토의견 작성)에 영향을 주지 않아야 한다
- **FR-007**: LLM API 키는 환경변수로 관리하며, 코드에 하드코딩하지 않아야 한다
- **FR-008**: LLM에 전송하는 데이터는 법령/조례의 공개 정보만 포함해야 한다 (개인정보 제외)
- **FR-009**: AI 요약 요청은 인증된 사용자만 가능해야 한다
- **FR-010**: LLM API 호출 시 타임아웃(30초)과 재시도(최대 2회)를 적용해야 한다
- **FR-011**: AI 분석은 자동 실행하지 않으며, 담당자의 명시적 요청(버튼 클릭)으로만 수행해야 한다
- **FR-012**: AI 분석이 완료된 대상은 해당 버튼을 비활성화하여 재실행을 방지해야 한다

### Key Entities

- **LlmAnalysisResult** (신규): LLM 분석 결과 캐시. ordinance_id, law_id, analysis_type (summary/review_draft), input_hash, prompt, response_text, model_name, token_usage, created_at
- **OrdinanceReview** (수정): `is_ai_generated`, `ai_modified` 필드 추가

## Success Criteria

### Measurable Outcomes

- **SC-001**: AI 요약 생성 응답 시간 10초 이내 (최초 생성 시)
- **SC-002**: AI 요약 재조회 응답 시간 1초 이내 (저장된 결과 반환 시)
- **SC-003**: AI 검토의견 초안 채택률(수정 없이 제출) 30% 이상
- **SC-004**: LLM API 장애 시 기존 기능 정상 동작 100%
- **SC-005**: 담당자의 검토의견 작성 시간 50% 단축 (AI 초안 활용 시)
