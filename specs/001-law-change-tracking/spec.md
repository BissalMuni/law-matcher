# Feature Specification: 개정법령 변경이력 관리

**Feature Branch**: `001-law-change-tracking`
**Created**: 2026-02-27
**Status**: Draft
**Input**: User description: "개정법령 변경이력 관리 - 상위법령 동기화 후 변경사항 감지, 승인/반려 워크플로우, 일괄처리, Excel 내보내기"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 법령 변경사항 목록 조회 및 필터링 (Priority: P1)

관리자가 상위법령 동기화 후 감지된 변경사항 목록을 다양한 조건으로 조회하여, 어떤 법령이 어떻게 변경되었는지 한눈에 파악할 수 있다.

**Why this priority**: 변경사항을 확인할 수 없으면 이후 승인/반려 등 모든 후속 작업이 불가능하므로 최우선 기능이다.

**Independent Test**: 법령 변경 데이터가 존재하는 상태에서 목록 페이지에 접근하여 필터링/검색이 정상 동작하는지 검증한다.

**Acceptance Scenarios**:

1. **Given** 법령 변경사항이 존재할 때, **When** 관리자가 변경이력 목록에 접근하면, **Then** 전체 변경사항이 페이지네이션과 함께 표시된다
2. **Given** 변경사항 목록이 표시된 상태에서, **When** 상태(대기/검토중/승인/반려), 소관부처, 동기화 일자, 개정유형 등으로 필터링하면, **Then** 조건에 맞는 변경사항만 표시된다
3. **Given** 변경사항 목록이 표시된 상태에서, **When** 법령명으로 검색하면, **Then** 법령명에 해당 키워드가 포함된 변경사항만 표시된다
4. **Given** 동기화 시 API 응답 상태가 다양할 때(성공/미응답/미발견), **When** API 응답 상태로 필터링하면, **Then** 해당 상태의 변경사항만 표시된다

---

### User Story 2 - 변경사항 상세 조회 (Priority: P1)

관리자가 개별 변경사항의 상세 정보(변경 전/후 값, 소관부처, 동기화 정보)를 확인하여 승인 여부를 판단할 수 있다.

**Why this priority**: 상세 정보 없이는 변경의 실질적 내용을 파악할 수 없어 의사결정이 불가능하다.

**Independent Test**: 특정 변경사항 클릭 시 상세 정보(변경 전/후 비교 포함)가 정확히 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 변경사항 목록이 표시된 상태에서, **When** 특정 변경사항을 선택하면, **Then** 법령명, 변경 전 값, 변경 후 값, 소관부처, 동기화 일자, 동기화 배치, API 상태, 처리 상태가 표시된다
2. **Given** 변경 전/후 값이 존재할 때, **When** 상세 화면을 보면, **Then** 변경된 항목(법령명, 공포일, 시행일, 개정유형 등)이 비교 형태로 표시된다
3. **Given** 변경사항이 이미 처리(승인/반려)된 경우, **When** 상세 화면을 보면, **Then** 처리자, 처리일시, 처리 메모가 함께 표시된다

---

### User Story 3 - 변경사항 개별 승인/반려 (Priority: P1)

관리자가 검토 완료된 변경사항을 승인하여 법령 정보를 최신화하거나, 반려하여 변경을 무시할 수 있다.

**Why this priority**: 변경사항을 법령 데이터에 실제 반영하는 핵심 워크플로우이다. 승인 시 상위법령 테이블이 갱신되어야 한다.

**Independent Test**: 대기 상태의 변경사항을 승인하면 법령 정보가 갱신되고, 반려하면 상태만 변경되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 대기(pending) 상태의 변경사항이 있을 때, **When** 관리자가 승인 버튼을 클릭하고 메모를 입력하면, **Then** 변경사항 상태가 '승인'으로 변경되고 상위법령 테이블에 변경 후 값이 반영된다
2. **Given** 대기(pending) 상태의 변경사항이 있을 때, **When** 관리자가 반려 버튼을 클릭하고 사유를 입력하면, **Then** 변경사항 상태가 '반려'로 변경되고 법령 정보는 변경되지 않는다
3. **Given** 이미 승인 또는 반려된 변경사항이 있을 때, **When** 관리자가 재처리를 시도하면, **Then** 처리가 거부되고 이미 처리되었음을 안내한다

---

### User Story 4 - 변경사항 일괄 승인/반려 (Priority: P2)

관리자가 여러 변경사항을 한 번에 선택하여 일괄 승인 또는 반려 처리할 수 있다.

**Why this priority**: 동기화 시 수십~수백 건의 변경사항이 감지될 수 있으며, 개별 처리는 비효율적이다.

**Independent Test**: 목록에서 복수 변경사항 체크 후 일괄 승인/반려 버튼 클릭 시 모두 처리되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 대기 상태의 변경사항이 여러 건 있을 때, **When** 관리자가 복수 항목을 선택하고 일괄 승인을 클릭하면, **Then** 선택된 모든 항목이 승인 처리되고 각각의 법령 정보가 갱신된다
2. **Given** 대기 상태의 변경사항이 여러 건 있을 때, **When** 관리자가 복수 항목을 선택하고 일괄 반려를 클릭하면, **Then** 선택된 모든 항목이 반려 처리된다
3. **Given** 선택 항목 중 이미 처리된 건이 포함되어 있을 때, **When** 일괄 처리를 실행하면, **Then** 미처리 건만 처리되고, 이미 처리된 건의 수가 안내된다

---

### User Story 5 - Excel 내보내기 (Priority: P2)

관리자가 현재 필터 조건에 맞는 변경사항 목록을 Excel 파일로 내보내어 오프라인 보고서 작성이나 공유에 활용할 수 있다.

**Why this priority**: 보고서 제출, 외부 공유 등 업무 활용을 위한 부가 기능이다.

**Independent Test**: 필터 적용 후 내보내기 버튼 클릭 시 Excel 파일이 다운로드되고, 내용이 화면 목록과 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 필터가 적용된 변경사항 목록이 있을 때, **When** 관리자가 Excel 내보내기를 실행하면, **Then** 현재 필터 조건에 맞는 전체 데이터가 Excel 파일로 다운로드된다
2. **Given** 내보내기된 Excel 파일을 열면, **Then** 법령명, 변경항목, 변경 전/후 값, 상태, 소관부처, 동기화 일자 등 주요 컬럼이 포함되어 있다

---

### User Story 6 - 변경이력 통계 조회 (Priority: P2)

관리자가 상태별/부서별 변경사항 통계를 조회하여 전체 현황을 파악할 수 있다.

**Why this priority**: 전체 현황을 수치로 파악해야 미처리 건 관리와 업무 우선순위 판단이 가능하다.

**Independent Test**: 통계 화면에서 상태별/부서별 집계가 실제 데이터와 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 변경사항 데이터가 존재할 때, **When** 통계를 조회하면, **Then** 상태별(대기/검토중/승인/반려) 건수가 표시된다
2. **Given** 변경사항 데이터가 존재할 때, **When** 통계를 조회하면, **Then** 소관부처별 변경 건수가 표시된다

---

### User Story 7 - 특정 법령의 변경 이력 추적 (Priority: P3)

관리자가 특정 법령에 대한 전체 변경 이력을 시간순으로 조회하여 해당 법령의 변경 패턴을 파악할 수 있다.

**Why this priority**: 개별 법령의 이력 추적은 심층 분석이 필요할 때 사용하는 부가 기능이다.

**Independent Test**: 특정 법령 ID로 이력 조회 시 해당 법령의 모든 변경 기록이 시간순으로 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 특정 법령에 대한 변경 이력이 여러 건 있을 때, **When** 해당 법령의 이력을 조회하면, **Then** 모든 변경 기록이 최신순으로 표시된다
2. **Given** 전체 변경 이력 요약을 요청할 때, **When** 이력 요약을 조회하면, **Then** 법령별 총 변경 횟수와 최근 변경일이 표시된다

---

### User Story 8 - 동기화 배치 및 일자 관리 (Priority: P3)

관리자가 동기화가 수행된 배치 정보와 일자 목록을 확인하여 특정 시점의 동기화 결과만 조회할 수 있다.

**Why this priority**: 동기화 이력 관리는 데이터 추적과 디버깅에 필요한 운영 기능이다.

**Independent Test**: 동기화 배치 목록 조회 및 특정 배치의 변경사항 필터링이 동작하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 여러 차례 동기화가 수행되었을 때, **When** 동기화 배치 목록을 조회하면, **Then** 각 배치의 동기화 일시와 건수가 표시된다
2. **Given** 동기화 일자 목록이 표시될 때, **When** 특정 일자를 선택하면, **Then** 해당 일자에 감지된 변경사항만 필터링된다

---

### Edge Cases

- 동기화 중 네트워크 오류가 발생하면 어떻게 되는가? → 해당 법령은 API 응답 상태가 '미응답'으로 기록되고, 다음 동기화 시 재시도된다
- 동일 법령에 대해 같은 동기화 배치에서 중복 변경이 감지되면? → 동기화 배치 ID와 법령 ID 조합으로 중복을 방지한다
- 승인 처리 중 법령 정보가 이미 다른 경로로 변경되었으면? → 승인 시점의 변경 후 값으로 덮어쓰며, 충돌은 이력으로 추적 가능하다
- 필터 조건에 맞는 변경사항이 0건이면? → 빈 목록과 안내 메시지를 표시한다
- Excel 내보내기 시 대량 데이터가 있으면? → 현재 필터 조건의 전체 결과를 포함하되, 시스템이 허용하는 최대 행 수까지 내보낸다

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 상위법령 동기화 후 감지된 변경사항 목록을 페이지네이션하여 제공해야 한다
- **FR-002**: 시스템은 변경사항을 상태(대기/검토중/승인/반려), API 응답 상태(성공/미응답/미발견), 소관부처, 동기화 일자, 검색어, 개정유형으로 필터링할 수 있어야 한다
- **FR-003**: 시스템은 각 변경사항의 변경 전/후 값을 비교 형태로 표시해야 한다
- **FR-004**: 관리자는 개별 변경사항을 승인하거나 반려할 수 있어야 하며, 처리 시 메모/사유를 기록할 수 있어야 한다
- **FR-005**: 승인 시 시스템은 해당 법령의 정보를 변경 후 값으로 자동 갱신해야 한다
- **FR-006**: 관리자는 복수의 변경사항을 선택하여 일괄 승인 또는 일괄 반려할 수 있어야 한다
- **FR-007**: 시스템은 현재 필터 조건에 맞는 변경사항을 Excel 파일로 내보낼 수 있어야 한다
- **FR-008**: 시스템은 상태별/소관부처별 변경사항 통계를 제공해야 한다
- **FR-009**: 시스템은 특정 법령의 전체 변경 이력을 시간순으로 제공해야 한다
- **FR-010**: 시스템은 동기화 배치 목록과 동기화 일자 목록을 제공하여 특정 시점 필터링이 가능해야 한다
- **FR-011**: 이미 처리(승인/반려)된 변경사항은 재처리가 불가능해야 한다
- **FR-012**: 변경사항 처리 시 처리자, 처리일시, 처리 메모가 자동 기록되어야 한다
- **FR-013**: 관리자 권한이 없는 사용자는 승인/반려 기능에 접근할 수 없어야 한다

### Key Entities

- **법령 변경사항 (Law Change)**: 동기화 시 감지된 개별 변경 기록. 대상 법령, 변경 전/후 값, 동기화 일자, 동기화 배치 ID, API 응답 상태, 처리 상태, 처리자 정보, 처리 메모를 포함한다
- **상위법령 (Law)**: 변경 감지 대상이 되는 법령. 변경사항 승인 시 이 엔티티의 값이 갱신된다
- **동기화 배치 (Sync Batch)**: 한 번의 동기화 실행 단위. 배치 ID로 동일 실행 시점의 변경사항을 그룹핑한다

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 관리자가 변경사항 목록을 조회하고 필터링하는 데 3초 이내로 결과가 표시된다
- **SC-002**: 1건의 변경사항을 상세 조회하고 승인/반려하는 전체 과정이 1분 이내에 완료된다
- **SC-003**: 50건의 변경사항을 일괄 승인/반려하는 데 10초 이내에 처리가 완료된다
- **SC-004**: 승인된 변경사항의 100%가 상위법령 정보에 정확히 반영된다
- **SC-005**: 필터 조건이 적용된 상태에서 내보내기한 Excel 파일의 데이터가 화면 표시 내용과 100% 일치한다
- **SC-006**: 관리자가 아닌 사용자가 승인/반려 기능에 접근 시 100% 차단된다

## Assumptions

- 법령 변경사항은 법제처 API(MOLEG) 동기화를 통해 자동 감지되며, 수동 생성은 지원하지 않는다
- 변경 전/후 값은 구조화된 형태로 저장되며, 주요 비교 항목은 법령명, 공포일, 시행일, 개정유형, 소관부처 등이다
- 동기화는 백그라운드 작업으로 실행되며, 변경이력 관리는 동기화 이후 감지된 결과를 대상으로 한다
- 일괄 처리 시 이미 처리된 건은 건너뛰고 미처리 건만 처리한다
- Excel 내보내기는 현재 필터 조건의 전체 결과를 포함한다

## Scope Boundaries

### 포함 범위
- 변경사항 목록 조회/필터링/검색
- 변경사항 상세 조회 (변경 전/후 비교)
- 개별 및 일괄 승인/반려 워크플로우
- Excel 내보내기
